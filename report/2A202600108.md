## 📊 Kết Quả Từng Bước Thực Hiện

### Bước 1: Thực Nghiệm Cục Bộ và Theo Dõi Thí Nghiệm với MLflow
* Đã thực hiện chạy nhiều thí nghiệm trên dữ liệu Phase 1 để tìm siêu tham số tối ưu.
* Kết quả quét siêu tham số tốt nhất:
  * `n_estimators`: `100`
  * `max_depth`: `20`
  * `min_samples_split`: `2`
  * **Độ chính xác (Accuracy) đạt được cao nhất trên tập Phase 1:** `0.6820`
* Giao diện MLflow UI đã lưu trữ đầy đủ lịch sử các lần chạy thí nghiệm kèm theo các chỉ số và mô hình lưu dưới dạng artifact.

---

### Bước 2: Xây Dựng Pipeline CI/CD Tự Động với GitHub Actions
* Đã cấu hình thành công Pipeline CI/CD gồm 4 Jobs chạy theo trình tự:
  1. **Unit Test:** Chạy pytest tự động kiểm thử code huấn luyện trên tập dữ liệu nhỏ giả lập trong bộ nhớ.
  2. **Train:** Xác thực cloud storage, kéo dữ liệu từ DVC S3 remote, huấn luyện mô hình thực tế, lưu metrics và upload model lên Cloud Storage (S3).
  3. **Eval:** Kiểm tra điều kiện chất lượng (Accuracy >= 0.70).
  4. **Deploy:** SSH kết nối vào máy ảo để cập nhật và khởi động lại dịch vụ API FastAPI phục vụ suy luận (`mlops-serve`).
* **Hành vi thực tế ở Bước 2:**
  * Độ chính xác của mô hình khi huấn luyện chỉ trên tập dữ liệu Phase 1 là **`0.6480`**, nhỏ hơn ngưỡng chất lượng tối thiểu **`0.70`**.
  * **Hành vi MLOps mong đợi hoạt động chính xác:** Job **`Eval`** đã chặn luồng deploy (báo đỏ/failed tại Eval Gate), không cho phép triển khai mô hình chất lượng kém lên máy chủ production!

---

### Bước 3: Huấn Luyện Liên Tục Khi Có Dữ Liệu Mới (Continuous Training)
* Đã mô phỏng quy trình bổ sung dữ liệu trong thực tế bằng cách ghép tập `train_phase2.csv` (2998 mẫu mới) vào tập huấn luyện, nâng tổng số mẫu lên **`5996`** mẫu.
* Sử dụng DVC để phiên bản hóa tập dữ liệu mới và thực hiện `dvc push` đồng bộ lên S3 Bucket `lab21-2a202600108`.
* Sau khi thực hiện `git commit` file DVC `.dvc` và push lên nhánh `master` trên GitHub, pipeline Actions tự động kích hoạt:
  * Mô hình được huấn luyện lại trên tập dữ liệu mới đầy đủ.
  * **Độ chính xác (Accuracy) nâng lên vượt bậc:** Đạt **`0.7580`** (vượt qua ngưỡng tối thiểu **`0.70`** của Eval Gate).
  * Job **`Eval`** thông báo **PASSED** thành công và chuyển giao sang job **`Deploy`**.
  * Máy chủ API FastAPI (`mlops-serve`) tự động tải model mới nhất từ S3 và khởi động lại suôn sẻ!

## 🌐 Kiểm Thử Endpoint Trên Máy Chủ Thực Tế

Sau khi triển khai thành công, API FastAPI đã chạy ổn định trên cổng `8000` của máy ảo AWS EC2 (`98.81.238.19`).

### 1. Kiểm tra sức khỏe (Health Check)
```bash
curl http://98.81.238.19:8000/health
```
**Kết quả phản hồi:**
```json
{"status": "ok"}
```

### 2. Gửi yêu cầu suy luận thực tế (Inference Prediction)
```bash
curl -X POST http://98.81.238.19:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"features": [7.4, 0.70, 0.00, 1.9, 0.076, 11.0, 34.0, 0.9978, 3.51, 0.56, 9.4, 0]}'
```

```json

```

## 🏆 Đánh Giá Tổng Kết
Hệ thống MLOps đã liên kết thành công các thành phần:
1. **DVC** quản lý dữ liệu lớn trên AWS S3.
2. **MLflow** quản lý thí nghiệm và siêu tham số cục bộ.
3. **GitHub Actions** tự động hóa vòng phản hồi (Feedback Loop) tích hợp liên tục và triển khai liên tục (CI/CD/CT).
4. **FastAPI & Systemd** duy trì ứng dụng phục vụ trực tuyến trên đám mây AWS EC2 bền bỉ, sẵn sàng tiếp nhận dữ liệu mới bất kỳ lúc nào chỉ bằng một lệnh push.
